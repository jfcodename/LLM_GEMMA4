Fundamentos

7 princípios do cérebro que faltam nos transformers

1. Event-driven (spike)
Neurônio só transmite quando ativo. Transformers calculam tudo, sempre. SNN: ~95% dos neurônios silenciosos.
2. Adições, não multiplicações
Spikes são binários. MACs se tornam AC (Accumulate). Reduz energia 8–10× em hardware neuromorfico.
3. Memória de trabalho limitada
Hippocampus retém apenas tokens críticos. Análogo: KV cache seletivo — evictar tokens de baixa importância.
4. Hierarquia de frequência
Córtex visual processa local → global. Gemma já faz SWA+full-attention em camadas alternadas.
5. Gating neuromodular
Dopamina/serotonina modulam quais circuitos ativar. Análogo: MoE routing, per-layer gates.
6. Codificação preditiva
Cérebro transmite apenas surpresa (erro de previsão). Análogo: speculative decoding, delta caching.
7. Temporalidade
Informação codificada no timing dos spikes, não só na taxa de disparo. Análogo: RoPE + timestep multi-step.
+ Especialização de experts
Áreas cerebrais se especializam. Broca vs Wernicke. Análogo direto: MoE — 128 experts, 2 ativos.

Testado

Quantização — estado da arte 2025

W4A16 (NF4/GGUF/AWQ/GPTQ): 4× redução de memória. Gemma 4 27B → ~14GB. Acc degradação <1%. Já disponível via unsloth/llama.cpp.
W8A8 (SmoothQuant): Acelera prefill e decode. 2× speedup. Bom ponto de equilíbrio.
NVFP4 (NVIDIA): Otimizado para H100/Blackwell. nvidia/Gemma-4-31B-IT-NVFP4 já existe. Máximo throughput em datacenter.
W4A8 (QQQ/QuIP): Acelera ambas as fases. 3.67× kernel speedup vs FP16 GEMM. Acc degradação moderada em reasoning.
KV cache INT8: Reduz memória de KV ~50%. Combinar com GQA já existente dá redução total de ~4–8×.
KV cache INT4/FP8: Mais agressivo. Funciona bem com SnapKV/H2O (tokens importantes em FP8, resto descartado).
W2/Ternary: 16× compressão. Acc cai ~5–15%. QuIP# e AQLM tentam recuperar, mas ainda pesquisa.

Neuroinspired

Esparsidade — o princípio mais cerebral

O cérebro opera com ~95% dos neurônios silenciosos a qualquer momento. Transformers padrão: 0%. Esta é a maior lacuna e maior oportunidade.

Testado
SparseGPT / Wanda (unstructured, 50–60%) Zera pesos individualmente. SparseGPT: iterative weight update com Hessian. Wanda: magnitude × input activation, one-shot. 60% sparsidade com perplexidade quase igual.
Testado
Structured pruning (MLP channels) Remove neurônios inteiros do MLP intermediate (10240→5120). Speedup real em CPU/GPU sem hardware especializado. Combina com quantização.
Testado
ReLU LLMs (substituição de ativação) GELU→ReLU²: ativação vira esparsa naturalmente (~50–80% zeros). SparseGPT + ReLU: speedup real. Gemma usa GELUTanh — candidata ideal.
Testado
Token sparsification (STATA) Descarta tokens de baixa importância durante forward pass. Em Spiking Transformers, timestep-wise anchor token garante precisão. Reduz FLOPs em 30–40%.
SNN puro
SpikingBrain conversion pipeline Converte GELUTanh → adaptive spiking neurons. Threshold adaptativo por neurônio. 69% sparsidade de ativação. KV cache INT8. 1.5h/GPU de calibração.
Novo
Per-layer gate como preditor de esparsidade O per_layer_input_gate (2560→256) já existe em Gemma 4. Usar a norma da saída como score de importância de neurônio → sparse MLP dinâmico sem retreino.

Crítico

Otimização de atenção e KV cache

Testado
FlashAttention 3 Kernel fused para GPU. Evita materializar a matriz de atenção completa. Já essencial — usar com Triton para as camadas globais (q=4096).
Testado
H2O / SnapKV — KV eviction por atenção Descarta tokens com baixo peso de atenção acumulado. SnapKV: observa padrão de atenção no prefill e poda KV para decoding. 80–90% do KV descartável.
Testado
RetroAttention / Quest (non-eviction sparse KV) Preserva KV completo mas carrega apenas tokens relevantes por step. Evita erros cumulativos de evicção. Top-k pages via similaridade Q×K summary.
Testado
StreamingLLM (attention sink) Mantém tokens iniciais (sinks) + janela deslizante. Compatível com as camadas SWA de Gemma 4. Memória constante O(1) para contextos longos.
SNN
Linear attention (O(n) vs O(n²)) SpikingBrain-7B: substitui full-attention por linear attention + SWA interleaved. Gemma 4 já tem SWA local — converter as globais para linear seria o próximo passo.
Novo
SALS — Sparse Attention in Latent Space Comprime KV no espaço latente antes de aplicar RoPE. Reduz rank efetivo do KV cache. Compatível com o RoPE do Gemma 4.
Testado
PagedAttention (vLLM) Memória de KV em páginas não-contíguas. Reduz fragmentação. Fundamental para serving em produção. Já suportado para Gemma 4.

Pipeline SNN

SpikingBrain: roteiro para converter Gemma 4

Baseado no resultado da Academia Chinesa de Ciências — converteram Qwen2.5-7B em 1.5h com ~2% do compute de treino do zero.

Passo 1
Continual pre-training (CPT) com extensão de contexto ~150B tokens com janela longa. Estabiliza distribuições de ativação antes da conversão spiking. Para Gemma 4 E2B: ~50B tokens suficientes.
Passo 2
Converter full-attention → linear + SWA hybrid Camadas globais (posições 5,11,17,23,29,35,41 em Gemma 4) → linear attention. Camadas locais SWA mantidas. Treino lightweight para recuperar acc.
Passo 3
Adaptive spiking neurons (substituição de GELUTanh) Threshold por neurônio calibrado em dataset pequeno. Fase 1 (otimização): conta inteira de spikes. Fase 2 (inferência): expande em spike train esparso binário.
Passo 4
Quantização pós-spiking: weights + KV cache → INT8 Após calibração de threshold, quantizar pesos. KV cache INT8. Conjunto: spike sparsity + quantização = redução de energia até 97.7%.
Passo 5
SFT final para recuperar accuracy Fine-tuning supervisionado em dados de instrução. Recupera degradação residual. SpikingBrain reporta competitivo vs Qwen2.5 base em benchmarks padrão.

Atenção

Limitações e riscos do pipeline SNN

Ganho de energia real só em hardware neuromorfico (Intel Loihi 2, IBM NorthPole). Em GPU NVIDIA convencional, o benefício é via esparsidade computacional, não eliminação de MACs.
Acc em reasoning/math pode degradar com linear attention. SpikingBrain-76B (MoE híbrido) preserva melhor que o 7B puro.
Gemma 4 multimodal (vision + audio) complica: towers precisam de conversão separada ou manter em FP16/INT8 clássico.
